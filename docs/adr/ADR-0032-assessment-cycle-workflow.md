# ADR-0032: 평가 회차·워크플로·증빙 관리

- 상태: 제안 (초안)
- 작성일: 2026-09-03
- 선행: ADR-0031(역할·권한 모델)
- 관련: ADR-0029(cascade), ADR-0030(테넌트 소유권), ADR-0025(테넌트 자동 격리), ADR-0020(제로 추상화)

---

## 1. 배경

ADR-0031에서 역할을 정의했으나 "언제 무엇을 하는가"가 정해지지 않았다.
증빙 편집 권한이 **평가 마감 여부**에 달려 있고, 마감은 **평가 회차**의 상태이므로
회차 개념 없이는 증빙 관리를 구현할 수 없다.

본 ADR은 다음을 다룬다.

- 평가 회차 정의와 생성
- 활동별 워크플로와 승인 단계
- 회차 마감과 그 이후 권한 변화
- 증빙 관리
- 감사추적

## 2. 결정

### 2.1 평가 회차는 전담부서가 생성한다

회차는 `assessor`(전담부서)가 생성한다. 통제책임자는 회차를 만들 수 없다.

**대상 통제는 자동으로 묶인다.** 회차 생성 시 통제를 하나씩 고르는 것이 아니라,
통제의 **평가주기** 속성으로 대상이 결정된다.

- 통제마다 평가주기를 갖는다: 주 / 월 / 분기 / 반기 / 연
- 회차는 주기를 지정해 생성한다 (예: "2026년 1분기 운영평가" → 분기 주기 통제가 대상)
- 따라서 회차는 주기별로 병렬 운영된다

**주기 지원 범위** — 주·월·분기·반기·연 5종을 지원한다. 최소 단위는 주다.

일 단위는 지원하지 않는다. 회차를 매일 생성하고 증빙을 매일 등록해야 하므로
실무가 감당할 수 없다. 시스템이 지원해도 사용되지 않으면 유지 비용만 남는다.

자금 이체처럼 매일 발생하는 통제는 주 단위 회차에서 해당 기간의 표본을
추출해 테스트하는 방식으로 대응한다. 표본 선정 방식은 Test 모듈 설계 시 다룬다.

### 2.2 설계평가 회차와 운영평가 회차는 독립이다

**두 회차는 서로 참조하지 않는다.**

| | 설계평가 | 운영평가 |
|---|---|---|
| 무엇을 보는가 | 통제가 실무와 맞고 위험을 잡도록 설계됐는가 | 설계대로 실제 운영됐는가 |
| 글로벌 용어 | design effectiveness | operating effectiveness |
| 통상 주기 | 연 1회 또는 설계변경 시 | 통제별 평가주기 |
| 회차 | 독립 | 독립 |

설계평가와 운영평가는 각각 독립적으로 회차를 열고 닫는다.
같은 회차 안에서 둘을 함께 처리하지 않는다.

**근거** — 주기가 다르고, 판단 대상이 다르며, 결과가 서로를 대체하지 않는다.
설계가 부적합하면 운영이 아무리 잘 돼도 통제가 작동하지 않으므로 별도로 본다.

### 2.3 활동 워크플로

ADR-0031 §2.5의 매핑을 회차 위에서 구체화한다.

| 활동 | 수행 | 승인 1(선택) | 승인 2 |
|---|---|---|---|
| 설계 / 설계변경 | 통제책임자 | 부서승인자 | 평가자 |
| 설계평가 | 평가자 | — | 내부회계관리자 |
| 테스트(자체점검) | 통제책임자 | 부서승인자 | — |
| 운영평가 | 평가자 | — | 내부회계관리자 |

**부서승인 단계는 테넌트 정책 토글로 켜고 끈다**(ADR-0031 §2.6).
인원이 적은 회사는 이 단계를 끄고 운영한다.

**내부회계관리자 승인은 개별 통제가 아니라 회차 전체에 대해 이뤄진다**(§2.6).

### 2.4 회차 마감은 회차 단위로만 한다

**통제 단위 마감은 두지 않는다.** 통제 50개를 개별로 닫게 하면 조작이 번잡하고,
"이 회차가 끝났는가"라는 질문에 답할 수 없다.

### 2.5 미완 상태에서도 마감할 수 있다 — 단 사유를 남긴다

회차 내 일부 통제가 완료되지 않아도 마감을 허용한다.

- 마감 시 미완 통제 목록을 명시적으로 제시한다
- 미완 사유 입력이 필수다. 사유 없이는 마감 불가
- 미완 내역은 회차 기록에 보존된다

**근거** — 막으면 회차가 영원히 닫히지 않고, 조용히 마감하면 무엇이 빠졌는지
알 수 없다. 실무에서 기한 제약으로 미완이 발생하며, 감사인과 협의하여
처리하는 경우가 있으므로 시스템이 이를 차단해서는 안 된다.
미완 기록 자체가 감사 대응 자료가 된다.

ADR-0031 §2.4(이해상충을 막지 않고 경고+사유)와 같은 원칙이다.
**막지 않고 기록한다.**

### 2.6 최종 승인은 회차 전체에 대해 이뤄진다

마감된 회차에 대해 `icfr_manager`가 최종 승인한다.
승인되면 대표자·이사회 보고 절차로 넘어간다.

개별 통제 승인이 아니다. 회차 단위 승인이며, 승인 시점과 승인자가 기록된다.

### 2.7 증빙

**증빙은 통제 × 회차에 붙는다.** 통제에만 붙는 것이 아니다.

- 하나의 통제 × 회차에 증빙 여러 개가 붙을 수 있다
- 여러 사용자가 각자 증빙을 올릴 수 있다
- 업로더가 기록된다

**편집 권한은 회차 상태에 따라 달라진다.**

| 회차 상태 | 통제책임자 | 관리자 |
|---|---|---|
| 진행 중 | 업로드·수정·삭제 가능(기본) | 가능 |
| 마감됨 | **불가** | 승인 시 가능 |

진행 중 편집 허용 여부는 **테넌트 정책 토글**로 제어한다. 기본은 허용이다.
`icfr_manager`가 이를 금지로 전환할 수 있다.

**삭제는 물리 삭제가 아니다.** 누가 무엇을 언제 올렸다가 삭제했는지 기록이 남는다.
ADR-0029 §2.2의 원칙(유도 가능한 값을 저장하지 않고, 물리 변경 없이 상태로 표현)과
같은 방향이다.

**크기 상한을 두지 않는다.** 원본이 보존되어야 제도 운영 취지에 맞는다.
저장공간 압박은 §2.9 보존정책과 별도 아카이브 기능으로 대응하며,
필요 시 서버 용량을 증설한다.

### 2.8 감사추적

**"누가 무엇을 했는가"는 수행 기록에 남긴다. 배정 이력은 관리하지 않는다.**

- 각 활동 기록(설계·테스트·평가·승인)에 수행자와 수행 시각을 남긴다
- 역할 배정은 **현재 상태만** 저장한다. 배정 변경 이력을 별도 관리하지 않는다

**근거** — 감사에서 묻는 것은 "1분기 평가를 누가 했는가"이며,
그 답은 평가 기록에 있다. 배정 이력까지 관리하면 조직 변경 관리를
시스템이 떠안게 되는데 그것은 인사 영역이다.
감사인이 조직 변경 이력을 요구하면 회사의 인사 기록으로 대응한다.

ADR-0031 §5의 "평가 회차별 역할 변동" 미해결 항목을 이로써 해소한다.
ADR-0031 §2.8의 "당시 부서장이 누구였는가" 문제도 같은 방식으로 처리한다 —
승인 기록에 승인자가 남으므로 별도 스냅샷을 두지 않는다.

### 2.9 보존기간

**최소 5년을 시스템이 강제한다.** 5년 미만 설정은 불가하다.

근거: 내부회계관리제도 업무지침 — 내부회계관리제도에 따라 작성된 회계정보 및
관련 문서는 5년간 보관한다.

**기본값은 영구 보존**이며, 5년 이상 범위에서 `icfr_manager`가 회사 상황에 맞게
설정한다.

## 3. 영향 범위

| 대상 | 변경 |
|---|---|
| `baseline_controls` / instance | 평가주기 속성 추가 |
| 신규 | 평가 회차 (유형: 설계평가/운영평가, 주기, 기간, 상태) |
| 신규 | 활동 기록 (설계·설계변경·테스트·평가, 수행자, 수행시각) |
| 신규 | 승인 기록 (부서승인·평가자승인·최종승인) |
| 신규 | 증빙 (통제×회차, 업로더, 삭제 이력) |
| 신규 | 회차 마감 기록 (마감자, 미완 목록, 미완 사유) |
| 신규 | 테넌트 정책 설정 (부서승인 토글, 증빙 편집 토글, 보존기간) |
| MinIO | 증빙 파일 저장. 테넌트별 격리 필요 |

**모든 신규 테이블은 `AuditedBase`로 둔다.** ADR-0030 §2.3의 복합 FK 격리를
동일하게 적용한다.

## 4. 검증 조건

1. 분기 주기 통제만 대상인 회차를 생성 → 일/월 주기 통제가 포함되지 않음
2. 설계평가 회차와 운영평가 회차를 동시에 열 수 있고 서로 영향 없음
3. 미완 통제가 있는 회차를 마감 → 사유 없이는 거부, 사유 입력 시 마감 성공
4. 마감된 회차의 증빙을 통제책임자가 수정 시도 → 거부
5. 마감된 회차의 증빙을 관리자 승인 하에 수정 → 성공, 이력 기록됨
6. 증빙 삭제 후에도 "누가 언제 올렸다가 삭제했는지" 조회 가능
7. 증빙 편집 토글을 금지로 전환 → 진행 중 회차에서도 통제책임자 수정 거부
8. 보존기간을 5년 미만으로 설정 시도 → 거부
9. 평가 기록에서 수행자·수행시각 조회 가능
10. 다른 테넌트의 회차·증빙에 접근 불가 (ADR-0030 격리)

**3번과 6번이 핵심이다.**
3번은 §2.5(막지 않고 기록)가, 6번은 §2.7(물리 삭제 아님)이 구현됐는지 본다.

## 5. 미해결

- **아카이브 기능** — 장기 보존 데이터를 수정 불가 형태로 별도 공간에 보관하고,
  특정 기간의 설계·운영·평가·증빙·감사·보고 일체를 열람하는 기능.
  설계·운영·평가·보고 모듈이 모두 구현된 뒤에 가능하므로 별도 ADR로 다룬다.
  **본 ADR은 그때 아카이브 가능한 형태로 데이터를 쌓는 것까지만 책임진다** —
  이력 보존, 물리 삭제 금지, 시점 조회 가능.
- 표본 추출 방식 — 고빈도 통제를 주 단위 회차에서 평가할 때
  표본 크기와 선정 기준을 어떻게 정할지. Test 모듈 설계 시 다룬다
- 미비점(deficiency) 관리 — 평가 결과 부적합 시 개선계획으로 이어지는 흐름.
  개선계획 모듈 설계 시 함께 다룬다
- MinIO 테넌트 격리 방식 — 버킷 분리인지 경로 분리인지
- ADR-0031 §5의 `owner_name` 이관 판단은 여전히 미해결
