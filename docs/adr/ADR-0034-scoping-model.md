# ADR-0034: 스코핑(Planning & Scoping) 모델

- 상태: 제안 (초안)
- 작성일: 2026-09-22
- 관련: ADR-0033(EUC·IUC), ADR-0032(평가 회차), ADR-0031(역할·권한), ADR-0030(테넌트 소유권·템플릿 복사), ADR-0029(cascade·유도값 비저장), ADR-0020(제로 추상화)
- 1차 출처: `backend/seeds/4__내부회계관리제도_Scoping.xlsx` (실무 양식, FY2022 데이터)

## 1. 배경

스코핑은 제도 흐름상 RCM보다 앞에 온다. 중요성 기준을 정하고, 유의한 계정과목·주석을
가려내고, 그 계정을 업무프로세스와 연결한 뒤, IT 요소(GITC)를 식별한다.
현재 시스템에는 빈 메뉴로만 있다.

### 1.1 원천 양식

실무 양식이 방법론을 완결된 형태로 담고 있다. 계산식이 전부 있으므로
**회계기준을 해석해 새로 설계하지 않고, 양식을 옮긴다.**

| 단계 | 시트 | 로직 |
|---|---|---|
| ① 양적 중요성 | 1. 중요성 기준 | 벤치마크 × 비율 → 전반중요성 → × 설정율 = 수행중요성 |
| ② 질적 중요성 | 2.1~2.4 | 질적 10요소 H/M/L(3/2/1) 평균 |
| ③ 유의성 결론 | 2.1~2.4 | 양적 유의 **또는** 질적 유의 |
| ④ 프로세스 연계 | 2.1~2.4 | 계정별 업무프로세스 O/△ |
| ⑤ GITC | 3. GITC Scoping | 통제별 시스템·IPE·GITC 대상 여부·사유 |

양식은 2022년 데이터를 담고 있다. **양식 구조와 문구·원칙은 템플릿으로 쓰고,
2022년 금액은 쓰지 않는다**(§2.7).

## 2. 결정

### 2.1 스코핑은 회계연도 단위다

회계연도마다 스코핑 1건을 둔다. 회계연도 경계는 테넌트 정책의
회계연도 시작월을 따른다(3-2에서 도입).

대상은 **별도재무제표**다. 원천 양식이 "별도재무제표: 감사대상"으로 명시한다.
연결재무제표는 이번 범위 밖이다(§5).

### 2.2 상태 — 작성 중 → 검토 중 → 확정

중요성 기준은 회사가 정하고 외부감사인의 검토를 받아 확정한다.

| 상태 | 수정 | 전이 |
|---|---|---|
| 작성 중 | 가능 | → 검토 중 |
| 검토 중 | 가능 | → 확정 / → 작성 중 |
| 확정 | **불가** | → 작성 중 (재오픈, `icfr_manager` + 사유 필수, 이력 기록) |

**감사인 검토는 시스템 밖에서 이뤄지고, 그 결과를 `icfr_manager`가 기록한다.**
감사인·검토일·의견·증빙을 남긴다. `external_auditor`는 조회만 한다(ADR-0031 — 외부감사인은
어떤 생성·수정도 하지 않는다). 감사인이 시스템에서 직접 승인하는 구조가 아니다.

**확정 시 템플릿 배지가 남은 필드를 경고한다**(§2.7). 막지 않고, 개수와 확정 사유를 기록한다.
2022년 판단이 검토 없이 그대로 확정되는 것을 드러내기 위해서다.

### 2.3 양적 중요성

원천 수식을 그대로 옮긴다.

```
벤치마크 산출액   = ROUND(벤치마크 기준값 × 비율, 0)
전반중요성        = ROUND(벤치마크 산출액, -3)          ← 천원 단위 반올림
수행중요성(SMT)   = ROUND(전반중요성 × 설정율, 0)
```

- **벤치마크는 선택한다.** 여러 벤치마크를 나란히 계산해 비교하되, 전반중요성은 선택한 하나로 정한다.
  원천도 조정세전순이익과 매출액을 함께 계산하고 조정세전순이익을 택했다
- 벤치마크 종류: 조정세전순이익 / 매출액 / 총자산 / 총자본 / 총비용 / 영업활동현금흐름
- **조정세전순이익은 세전이익에서 비경상 항목을 조정**한다. 조정 항목과 사유를 기록한다
- **설정근거는 필수 입력**이다. 벤치마크와 비율을 왜 택했는지 감사에서 묻는다
- **가이드 범위를 벗어나면 경고하되 막지 않는다.** 원천 Note 1·2의 범위를 쓴다

| 항목 | 가이드 범위 | 원천 |
|---|---|---|
| 세전계속사업이익 비율 | 5 ~ 10% | Note 1 |
| 매출액 비율 | ⚠ 원천 "0.0 ~ 5%" — 오기 의심, §5 | Note 1 |
| 총자산 비율 | 1 ~ 2% | Note 1 |
| 총자본 비율 | 3% 이하 | Note 1 |
| 총비용 비율 | 3 ~ 5% | Note 1 |
| 영업활동현금흐름 비율 | 3 ~ 5% | Note 1 |
| 수행중요성 설정율 | 50 ~ 75% (기본 70%) | Note 2 |

매출액 범위는 확인 전까지 경고 판정에 쓰지 않는다.

### 2.4 계정 평가

대상은 4종이다 — 재무상태표 / 손익계산서 / 주석 / 현금흐름.

**양적 유의** = `|당기 금액| ≥ 수행중요성`

**질적 유의** = 질적 10요소 H/M/L(3/2/1) 평균 **≥ 2**

**2026-09-22 결정 — "이상(≥)"으로 한다.** 원천은 설명문이 "2를 초과하면 중요",
수식이 `>=2`로 서로 달랐다. 실제 적용되고 감사인 검토를 거친 것은 수식이며,
스코핑은 보수적으로 잡는 것이 원칙이다(수행중요성을 50~75%로 낮추는 것도 같은 이유).

"초과"로 바꾸면 원천에서 유의로 결론 난 16건이 비유의로 떨어진다. 그중
대손충당금·미수수익·리스부채·이연법인세자산 등은 RCM 통제와 EUC가 걸린 계정이다.
스코핑이 "유의하지 않다"고 하면 통제·EUC가 있는 계정이 범위 밖으로 빠지는 모순이 생긴다.

**문구를 "이상"으로 고쳐 템플릿에 넣는다. 기준값과 비교 방식은 테넌트 정책으로 둔다**
(기본 2, 이상). 감사인이 다른 기준을 요구하면 바로 바꿀 수 있어야 한다.

질적 10요소는 원천 문구를 그대로 쓴다(설계운영 적용기법 질적요소 42):
개별 거래의 규모·복잡성·동질성 / 추정·판단 개입 / 회계처리·보고의 복잡성 /
우발채무 발생가능성 / 특수관계자 거래 / 성격 변화·금액 변화 / 비경상 거래 /
회계기준 변경 / 법규·감독당국 강조 / 외부환경 변화

**10요소 중 하나라도 미입력이면 질적 판정은 "미평가"다.**
원천은 빈칸을 0으로 합산해 평균을 끌어내렸다 — 평가하지 않은 것이 "중요하지 않음"으로
나오는 과소평가다. ADR-0033(EUC 미평가)과 같은 원칙이다.

**유의성 결론** = 양적 유의 OR 질적 유의.
양적 N이고 질적 미평가면 결론도 미평가다.

**수동 판정을 허용하되 사유를 필수로 한다.** 원천에서도 일부 계정은 수식 대신 N을 직접
입력하고 사유를 적었다(예: 주식발행초과금 "실질적 변경가능성이 없는 항목"). 막지 않고 기록한다.
계산 결론과 수동 결론을 모두 보존한다.

금액은 **원 단위 하나로 저장**한다. 원천 주석 시트는 백만원 단위로 되어 있다 — 입력 시 환산한다.

### 2.5 계정 ↔ 업무프로세스 연계

| 표시 | 의미 |
|---|---|
| O | 주 프로세스 — 완전히 연계됨 |
| △ | 관련 프로세스 — 부분적으로 연계됨 |

연계 대상은 **RCM의 프로세스**다(테넌트 소유 baseline, ADR-0030).
스코핑과 RCM이 여기서 이어진다.

**유의한 계정인데 연계된 프로세스가 없으면 경고한다.** 스코핑 누락 신호다.

프로세스 id는 baseline·instance에 걸친 정체성 id라 FK를 걸 수 없다.
핸들러가 resolver로 존재를 검증한다(ADR-0033 5-1 정보 항목→통제와 같은 처리, ClaudeICFR.md 13.9-27 위험 승계).

### 2.6 GITC 스코핑

통제별로 기록한다. 회계연도 단위다.

| 항목 | 처리 |
|---|---|
| Key control 여부 | **RCM에서 참조.** 중복 저장하지 않는다 |
| 자동/수동 | **RCM에서 참조.** 중복 저장하지 않는다 |
| 관련 시스템 | 입력 |
| IPE(IUC) 문서 | **IUC 정보 항목을 참조**(ADR-0033). 문서명 텍스트로 두지 않는다 |
| GITC 대상 여부 | Yes / No / N/A |
| 대상 아님 사유 | No·N/A일 때 **필수** |

원천 양식은 Key control·자동수동·IPE 문서명을 텍스트로 다시 적었다. 시스템에서 이를
다시 저장하면 RCM·IUC와 어긋난다 — 오늘까지 저장소가 갈라져 생긴 문제를 여러 번 겪었다.

### 2.7 템플릿 — 미리 채우고, 수정하면 배지를 뗀다

**원천 양식을 기본 템플릿 중 하나로 둔다.** 새 회계연도 스코핑을 만들 때 템플릿 내용을
테넌트 스코핑으로 **복사**한다. 복사 이후는 테넌트가 독립적으로 관리한다(ADR-0030 §2.4와 같은 방식).
어느 템플릿·어느 버전에서 왔는지 기록한다.

**템플릿에 들어가는 것**
- 중요성 가이던스 문구(적용기법 문단 57·58·64~66), 질적 10요소 설명, 벤치마크 가이드 범위, 경영진주장(Note 4)
- 계정과목 목록(BS·PL), 주석 목록, 현금흐름 항목
- **계정별 질적 10요소 평가값(H/M/L)과 판단 근거 문구**
- 계정별 프로세스 연계(O/△)
- GITC 대상 아님 사유 문구
- 중요성 설정근거 문구

**템플릿에 넣지 않는 것**
- 2022년 금액 — 전부 제외
- 개인정보 — 원천 업무프로세스 시트에 감사인 담당자 이메일이 있다. 제외
- 옛 버전 잔재 — 주석 시트 헤더(FY2019), 현재 RCM에 없는 통제 코드

**배지 규칙**
- 템플릿에서 온 값에는 "템플릿 문구" 배지를 붙인다
- **사용자가 그 필드를 수정한 경우에만 배지를 뗀다.** 필드 단위다 — 한 계정의 한 요소를 고치면 그 요소만 떨어진다
- 같은 값으로 다시 저장하는 것은 수정이 아니다

**근거** — 계정별 평가값까지 미리 채우면 초기 입력이 쉬워지지만, 2022년 판단이 검토 없이
그대로 쓰일 위험이 있다. 배지가 "아직 회사가 직접 판단하지 않은 곳"을 보여주고,
확정 시 경고(§2.2)가 그것을 한 번 더 드러낸다.

### 2.8 재무제표 입력

**이번에는 두 경로다** — 수기 입력, 정형 엑셀 업로드(계정명·당기·전기 금액).

- 업로드된 계정명을 템플릿 계정과 매칭한다. **자동 매칭에 실패한 항목은 목록으로 드러내고
  사용자가 연결한다.** 조용히 버리지 않는다
- **PDF 등 임의 형식에서 계정·금액을 추출하는 것은 별도 ADR로 다룬다**(§5).
  추출 정확도 문제가 스코핑 계산 로직과 섞이면 둘 다 늦어진다.
  정형 입력 경로를 먼저 완성하면 추출은 그 앞단에 붙인다

### 2.9 값 상수는 한 곳에

재무제표 종류 / 벤치마크 종류 / 질적 요소 10종 / H·M·L / O·△ / GITC 대상 여부 / 스코핑 상태.
데이터에 있는 값만 나열하지 않는다(ClaudeICFR.md 13.9-40).

### 2.10 권한

작성·수정·상태 전이는 **`icfr_manager`**다. `external_auditor`는 조회만.
프론트 게이트는 `can_write`가 아니라 `tenant_roles`로 판정한다.
기존 가드(`require_write`)를 그대로 쓰지 않는다(13.9-35·41의 교훈).

실무에서 스코핑 작업은 전담부서가 하고 내부회계관리자가 승인한다.
전담부서를 테넌트 단위 역할로 둘지는 §5에 남긴다.

## 3. 영향 범위

| 대상 | 변경 |
|---|---|
| 신규 | 스코핑(회계연도·상태·검토 기록) |
| 신규 | 양적 중요성(벤치마크 계산·선택·조정 항목·설정근거) |
| 신규 | 계정 평가(재무제표 종류·금액·질적 10요소·수동 판정) |
| 신규 | 계정↔프로세스 연계 |
| 신규 | GITC 스코핑(통제별) |
| 신규 | 템플릿·템플릿 출처(필드 단위 배지) |
| 테넌트 정책 | 질적 기준값·비교 방식 |
| 대시보드 | Scoping 카드 — 현재 "준비중" |

**모든 신규 테이블은 `AuditedBase`**, 테넌트 격리 복합 FK(ADR-0030),
소프트 삭제 유니크는 **처음부터 부분 유니크**(13.9-35 ④, 13.9-42).
계산 결론(양적·질적·유의성)은 **저장하지 않고 조회 시 산출**한다(ADR-0029 §2.2).
단, 확정 시점의 결론은 스냅샷으로 남긴다 — 확정 후 정책 기준이 바뀌어도 확정 당시 판단이 보존되어야 한다.

## 4. 검증 조건

1. **원천 2022 수치로 계산 재현** — 조정세전순이익 4,818,843,993 × 5% → 전반중요성 **240,942,000**,
   × 70% → 수행중요성 **168,659,400**. 원천 캐시값과 일치 (테스트 픽스처로만 쓰고 시드하지 않는다)
2. 원천 질적 평가값으로 계산 → 원천 결론과 일치(≥2). 16건이 유의로 유지됨
3. 정책을 "초과"로 바꾸면 그 16건이 비유의로 바뀜 (설정이 동작함)
4. 질적 10요소 중 하나 미입력 → 질적 미평가, 양적 N이면 결론 미평가
5. 수동 판정 — 사유 없으면 거부, 계산 결론과 수동 결론이 모두 보존됨
6. 시드 직후 템플릿 값 전부 배지. 한 필드를 수정하면 그 필드만 배지 해제. 같은 값 재저장은 해제 안 됨
7. 확정 시 배지 남은 필드 개수 경고 + 확정 사유 기록
8. 확정 후 수정 거부. 재오픈은 `icfr_manager` + 사유, 이력 기록
9. 확정 후 정책 기준을 바꿔도 확정 스냅샷의 결론은 그대로
10. 유의 계정에 연계 프로세스 0 → 경고
11. GITC No·N/A → 사유 없으면 거부
12. 비율·설정율이 가이드 범위 밖 → 경고, 저장은 허용
13. 템플릿에 개인 이메일·2022 금액이 없음
14. `external_auditor` 쓰기 전부 거부
15. 다른 테넌트 스코핑 접근 불가 (postgres에서 확인)

**1·2·6번이 핵심이다.**
1·2번은 원천을 정확히 옮겼는지, 6번은 템플릿 배지가 필드 단위로 동작하는지 본다.

## 5. 미해결

- **PDF 등 임의 형식 재무제표 추출** — 별도 ADR. 자체 파서와 자사 문서 필터·분석 제품 활용을 함께 검토
- **매출액 비율 가이드 "0.0 ~ 5%"** — 통상 0.5~1%로 오기 의심. 확인 전까지 경고 판정에 쓰지 않는다
- **"검토했고 동의함"을 배지로 표시하는 방법** — 현재 규칙상 수정해야만 배지가 떨어진다.
  템플릿 판단에 동의하는 검토자는 배지를 뗄 방법이 없어 확정 경고가 계속 남는다.
  수정 없이 "확인" 표시를 허용할지 운영하며 판단
- **전년도 이월** — 다음 회계연도 스코핑을 전년도 확정본에서 복사할지 템플릿에서 새로 시작할지
- **전담부서 테넌트 역할** — 스코핑 작업자와 승인자(`icfr_manager`) 분리
- **원천 불일치** — GITC 시트 통제 130건(현재 RCM 93건), 업무프로세스 시트 하위프로세스 33개(현재 29개).
