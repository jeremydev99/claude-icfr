# ADR-0039: 외부 사용자 초대·접근 범위·MFA

- 상태: **채택** (2026-10-03 마스터 "전부 채택", 1단계 구현)
- 관련: ADR-0031(역할), ADR-0038(검토·승인 거버넌스·자기 승인 금지), 보안 1단계(13.9-71)
- 기준: NIST SP 800-63B(인증 강도 AAL2), ISO 27001 접근통제(A.5.15~5.18), SOC 2 CC6 — ICFR 시스템 자체의 IT일반통제(ITGC) 대상

## 1. 배경

회사마다 내부 직원 외에 시스템을 쓰는 외부 관련자가 있다. 그 범위와 책임이 달라 **한 가지 "외부" 권한으로는 묶을 수 없다**.
외부 사용자의 생성·권한·만료·정기 재확인은 감사인이 매년 확인하는 ITGC 항목이다 — 기록이 남아야 한다.

## 2. 결정

### 2.1 외부 사용자 4유형 (테넌트 역할)

| 유형 | 역할 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|---|
| 1 PA회계법인(ICFR 자문) | `external_advisor` (신규) | 일반관리자와 같은 작성·검토 요청·제안(단계 1로 판정) | 검토·승인·확정, 사용자·역할·정책 관리 |
| 2 외부감사인 | `external_auditor` (기존) | 전 항목 조회 | 모든 쓰기 |
| 3 감사위원회·사외이사 | `auditor` (기존) | 대시보드·Report·미비점·결재 이력 조회 | 모든 쓰기, 원장 세부 화면(1단계는 메뉴로 제한) |
| 4 세무·기장대리인 | `external_specialist` (신규) | **지정 모듈만 작성** — 기본 재무제표 | 그 밖의 모든 쓰기 |

- 외부 사용자는 관리자 1~3단계(승인권자)가 될 수 없다(ADR-0038 자기 승인 금지 유지).
- `auditor`·`external_auditor` 만 가진 계정은 **조회 전용**(`can_write` 확장 — 기존엔 `external_auditor` 만 막았다).

### 2.2 접근 범위·기간 — `external_profiles`

외부 사용자마다 테넌트별 **소속 법인·유형·모듈·유효기간(시작·종료)·상태**를 둔다. 인증 의존성(`get_current_user`)이
요청마다 확인해 **기간 밖이거나 해지면 403** — 화면 숨김이 아니라 서버가 막는다. 분기별 접근 재확인(누가·언제)을 기록한다.

### 2.3 초대 — 요청 → 승인 → 1회용 링크

```
초대 요청(책임·마스터) → 승인(마스터, 요청자 ≠ 승인자) → 1회용 링크(72시간, 토큰은 해시만 저장)
→ 수락: 이메일 확인·비밀번호 설정·비밀유지 동의·MFA 등록 → 접근 시작 → 종료일 자동 차단
```
메일 발송이 아직 없어 승인 화면이 링크를 한 번 보여 주고 담당자가 전달한다(메일 연결 후 자동 발송).
요청·승인·수락·해지가 거버넌스 이력에 남는다.

### 2.4 인증 — 비밀번호 + MFA(TOTP)

- **TOTP(RFC 6238, Google·Microsoft Authenticator)**. 비밀값은 Fernet 으로 암호화 저장(키는 서버 `MFA_ENC_KEY`, 없으면
  JWT 비밀값에서 파생). 복구 코드 10개(해시 저장, 1회용).
- 로그인 2단계: 비밀번호 확인 후 MFA 대상이면 토큰 대신 5분짜리 `mfa` 토큰 → 코드 확인 후 정식 토큰.
  등록 전이면 등록 화면(QR) → 첫 코드 확인 시 활성화.
- **의무 대상**: 외부 사용자 전원은 처음부터. 내부 마스터·책임관리자는 **2026-11-02부터**(30일 유예, `MFA_INTERNAL_REQUIRED_FROM`).
  그 밖의 사용자는 선택.
- 외부 사용자 갱신 토큰은 **8시간**(내부 1일).
- 관리자는 사용자 MFA 를 초기화할 수 있다(기기 분실) — 이력 기록.
- **다음 단계**: 패스키(WebAuthn) 선택 지원, OIDC/SAML SSO(법인 자체 계정), 문자·카카오는 예외 보조 수단.

## 3. 검증 조건

1. 초대 요청자 본인은 승인 409. 승인 전 링크 없음, 72시간 지나면 수락 410.
2. 수락 시 유형별 역할·범위가 생기고, 종료일 다음 날 요청은 403.
3. `external_specialist` 는 재무제표 쓰기 가능·스코핑 쓰기 403. `auditor` 만 가진 계정은 쓰기 403.
4. MFA 등록 사용자는 코드 없이 토큰을 받지 못한다. 틀린 코드 401, 복구 코드는 1회만.
5. 외부 사용자는 MFA 미등록이면 등록 화면으로만 진행된다.
