# ADR-0040 통제 ↔ 계정 연결 (자동 매칭 + 드래그 수정 + 2단계 승인)

- 상태: 채택 (2026-10-05, 마스터 지시 "기본은 자동 매칭, 안 되는 항목은 실무자가 드래그, 관리자·마스터 승인")
- 관련: ADR-0034(스코핑), ADR-0037(재무제표 계정 트리), ADR-0038(검토·승인 거버넌스), 13.9-78(커버리지 추정)

## 1. 배경
스코핑 커버리지(유의 계정 ↔ RCM 통제)는 RCM `related_accounts` 자유 텍스트를 이름으로 대조한 **추정**이었다.
상·하위 계정(매출액 ↔ 수입수수료), 표기 차이(감가상각누계액_건물), 2자 토큰 제외 때문에 운영 46개 유의 계정 중
19개가 "통제 없음"으로 나왔고, 감사인에게 "이 통제가 이 계정을 다룬다"를 근거로 보여 줄 수 없었다.

## 2. 결정
1. **구조화된 연결 표 `control_account_links`** — 통제(resolver 정체성 id) × 계정 키. 계정 키는 회사 계정
   체계(`fs_accounts.id`, 연도를 넘어 유지)이고, 재무제표 계정이 없는 주석은 `note:<정규화 이름>`.
2. **상태**: `draft`(작성 중) → `review`(결재 묶음) → `active`(확정). 자동 결과를 사람이 빼면 `dismissed`(다시 자동으로
   들어오지 않음). 활성 연결 해제는 `remove_state`(draft → review)로 같은 결재를 거친다.
3. **자동 매칭** — 이름 일치(exact), 같은 계정의 다른 이름(alias: 매출액↔영업수익, 판매비와관리비↔영업비용),
   상위 계정 일치 시 하위 전부(parent), 토큰 ⊂ 계정명(partial). 반대 방향 부분 일치는 다른 계정이라 제외하되
   괄호 보충 표기(`충당부채(장기근속급여)`)·주석 계정은 허용. 운영 실측: 유의 46개 중 36개에 후보.
4. **수정은 실무자**(일반관리자 이상·PA회계법인) — 보드에서 통제를 계정 위로 드래그(휴대폰은 통제 선택 → 계정 탭).
5. **승인은 제안 결재 재사용**(kind `control_link`) — "검토 요청" 시 초안 전부가 한 묶음, 책임관리자 1차(항목별·일괄)
   → 마스터 2차. **요청자는 1차·2차 어디서도 승인 불가**(`proposals.requested_by_id`). 반려 시 초안으로 복귀.
   결재 중 묶음은 하나만, 결재 중 연결은 잠김.
6. **커버리지**: 승인된 연결이 있는 계정은 `basis=linked`(확정), 없으면 기존 이름 추정(`estimated`).
7. 화면: `/rcm/links` — 연결 보드(좌 통제·우 계정, **고른 항목의 선만** 그림) + 매트릭스(행 유의 계정 × 열 프로세스).

## 3. 결과·제약
- 마이그레이션 `c5e7a9b1d3f6`(추가만): 새 표 1개 + `proposals.requested_by_id` + `proposal_items` 통제 칸 4개.
- 마스터가 직접 요청한 묶음은 2차 승인자가 없다(마스터 1명) — 실무자·책임관리자가 요청한다.
- 통제가 삭제·제외돼도 연결 행은 남는다(코드·이름 표기 보존). 보드는 resolver 결과에 있는 통제만 보여 준다.
- 다음: 매 결산 증감분석 통제처럼 여러 계정을 덮는 통제의 일괄 연결(다중 선택), 연도별 연결 스냅샷(스코핑 확정 시).
