# ADR-0041 직원 계정 설정 링크 — 관리자가 비밀번호를 모르게

- 상태: 채택 (2026-10-07, 마스터 결정)
- 관련: ADR-0039(외부 사용자·MFA — 같은 토큰 방식), 보안 1단계(13.9 2026-10-01), `ClaudeICFR.md` 13.9-99

## 배경
직원 계정은 시스템관리자가 비밀번호를 직접 입력해 만들고, 재설정도 관리자가 새 비밀번호를 입력했다.
관리자가 직원 비밀번호를 알게 되어 "누가 했는가"(감사 로그·결재 본인 확인)의 신뢰가 약해진다. 메일 발송 기반은 아직 없다.

## 결정
1. **계정 생성 기본 = 초대**: 이메일·이름·역할만 입력 → 계정은 `invite_pending`(아무도 모르는 임의 비밀번호, 로그인 불가) +
   **설정 링크** 발급. 직원이 `/setup/{토큰}` 에서 본인 비밀번호를 정하면 시작된다. 2단계 인증은 이후 로그인 때 기존 규칙대로.
2. **재설정 = 링크 발급**: 관리자는 링크만 전달. **링크를 쓰기 전까지 기존 비밀번호는 유효**(마스터 결정 — 편의 우선,
   탈취 대응은 비활성화·잠금으로).
3. **링크**: `secrets.token_urlsafe(32)`, DB 에는 SHA-256 해시만(`account_setup_tokens`), **72시간**, 한 번만,
   새로 발급하면 이전 미사용 링크 취소. 원문은 발급 응답에서 한 번만 보여 준다(메일이 없어 관리자가 복사·전달).
4. **비상용 직접 지정은 시스템관리자에게만 유지**(마스터 결정): 생성 시 비밀번호 입력·기존 reset-password.
   이때 `must_change_password` → 그 사용자는 **본인 비밀번호로 바꾸기 전까지** `/api/auth/me·change-password·logout·refresh`
   외 모든 API 가 403(서버 `get_current_user`), 화면은 닫을 수 없는 변경 창. 관리자가 정한 값과 같은 비밀번호로는 못 바꾼다.
5. **감사 로그**: 생성·링크 발급·비상 지정·본인 설정이 남고, 경로의 링크 토큰은 `***` 로 가린다(외부 초대 링크도 함께).
6. 권한은 종전과 같다(`require_admin` = 시스템관리자). 기존 계정·비밀번호는 바뀌지 않는다(새 열 기본값 false).

## 결과
- 마이그레이션 `c9e1a3b5d7f0`(추가만): `account_setup_tokens` 표, `users.invite_pending`·`must_change_password`.
- 후속: 메일 발송이 생기면 링크를 메일로 보내고 화면 복사는 보조로.
