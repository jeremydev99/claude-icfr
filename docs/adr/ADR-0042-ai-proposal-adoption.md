# ADR-0042 — AI 제안·채택 모델

- **상태**: 채택 (2026-10-13, 마스터 결정 — 운영 결정)
- **관련**: ADR-0038(검토·승인 거버넌스), 13.9-114(상단 알림), `ClaudeICFR.md` 13.9-116

## 1. 배경

내부회계 항목별 판단·문서를 사람이 빈칸에서 새로 쓰는 데 시간이 가장 많이 든다. 통제 활동은 사람이 수행하므로,
초안을 AI 가 만들고 사람이 채택·수정·승인하면 절차상 책임 구조는 그대로 두고 작성 시간을 줄일 수 있다.

## 2. 결정

### 2.1 흐름 (마스터 결정)
`(제안) AI → (채택 또는 수정해 반영) 담당자·내부회계 담당자 → (채택 내용 승인) 책임자 → (최종 승인) 내부회계관리자`

- 제안 기록의 최초 작성자는 `system:ai` 다. **책임 주체는 채택한 사람**이며 화면·보고서는 "AI 제안 → ○○ 채택 → ○○ 승인"으로 보인다.
- 채택 뒤의 승인은 각 문서의 기존 결재선(ADR-0038, 일정 전결라인 등)을 그대로 쓴다. **채택자는 승인할 수 없다**(자기 승인 금지).
- 샘플 테스트 수행·업로드한 사실 데이터(재무제표·증빙·결재 기록)는 제안 대상이 아니다.
- AI 가 없거나 멈춰도 사람이 직접 입력하는 경로는 남긴다.

### 2.2 제안 유형 — "언제(계기)·무엇을 보고(근거)"
| 유형 | 계기 | 근거 | 엔진 |
|---|---|---|---|
| ① 규칙형 | 날짜 | 전년도 자료·달력 | **규칙(LLM 없음)** — 결과가 항상 같고 감사 설명이 쉽다 |
| ② 데이터형 | 데이터 확정 | 시스템 안의 수치 | 계산 + Claude API(질적 판단 문장) |
| ③ 질문형 | 연 1회·변화 신호 | **현업 답변**·업로드 문서 | Claude API |
| ④ 점검형 | 상시 | 기존 데이터 간 모순 | 규칙 + Claude API(문장 점검) |

- **근거가 없으면 제안하지 않고 묻는다.** AI 는 현업 변화를 추측하지 않는다(RCM 은 ③ 질문지 + 시스템이 아는 변화만).
- 모든 제안은 계기·근거를 함께 저장·표시한다.

### 2.3 기록 — `ai_proposals`
제안 원문(`proposed`)·근거(`basis`)·계기(`trigger`)·엔진(`engine`: `rule:<이름>` / `claude:<모델>`)·상태
(`proposed → adopted | discarded | superseded`)·채택자·채택 시 원문 대비 변경(`adopted_changes`)을 남긴다.
"변경 없이 채택" 비율은 이 표로 센다(형식적 승인 점검).

### 2.4 엔진
Claude API(마스터 결정 — 사내 LLM 은 성능 부족 우려). 키는 서버 env 에만 둔다. 보내는 데이터는 제안에 필요한 최소한으로 한다.

### 2.5 착수 순서
① 일정(규칙형) → ④ 점검형 → ② 스코핑 → ③ RCM 질문지.

## 3. 결과
- 일정: 회계연도 종료 30일 전부터 다음 연도 일정안이 없으면, 전년도 승인본(없으면 일정안·표준 일정)을 1년 뒤로 옮기고
  주말·공휴일에 걸린 시작일은 다음 영업일, 종료일은 직전 영업일로 맞춘 초안을 만든다. 채택 전에는 상신할 수 없다.
- 매일 서버 작업(`python -m app.jobs.ai_daily`)이 계기를 확인한다. 화면에서 시스템관리자가 바로 실행할 수도 있다.
