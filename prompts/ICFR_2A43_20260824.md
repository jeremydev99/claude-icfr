# 2-A-4-3: 상위 3계층 resolver 배선 + CRUD 전환

작성일: 2026-08-24
근거 ADR: ADR-0029(cascade 시맨틱), ADR-0027(조회 resolver), ADR-0020(제로 추상화)
관련: ClaudeICFR.md 13.7 정정, 13.9-6

---

## 0. 배경

운영 서버에서 `GET /api/rcm/processes` 가 0건을 반환한다. 버그가 아니라 미배선이다.

- `resolve_processes` / `resolve_sub_processes` / `resolve_risks` 는
  `control_resolver.py:137,144,157` 에 **이미 구현**되어 있으나 호출처가 없다
  (유일한 호출: `tests/test_rcm_baseline.py`)
- `api/rcm.py` 의 `/processes`(78-83), `/sub-processes`(126-133), `/risks`(176-183) 는
  레거시 테이블을 직접 조회한다
- 운영은 `seed_baseline.py`(Baseline* 6모델만)로 구축돼 레거시가 비어 0건이 된다
- 로컬은 Phase 0~1 레거시 잔존(processes 9 / controls 95)이 있어 이 상태가 가려져 있었다

**따라서 로컬에서 정상 동작하는 것은 검증이 아니다.** 이 작업의 판정은 운영 기준이다.

## 1. 범위

**포함**
- 상위 3계층(process / sub_process / risk) 조회 API resolver 경유 전환
- 상위 3계층 CRUD를 overlay(instance) 기반으로 전환
- ADR-0029 cascade 시맨틱 구현
- envelope source 필드 확장 (Regina 협의 A안)
- 위를 검증하는 테스트

**제외 — 이번에 손대지 않는다**
- `upload-excel` 파서 분리 및 13.6 멀티헤더 0건 버그 → 별건.
  읽는 경로를 고치기 전에 쓰는 경로를 고치면 파서를 두 번 수정하게 된다
- xfail 6건 → 본 작업으로 자연 해소되는 건이 섞여 있다. 완료 후 남은 것만 별건 처리
- 레거시 테이블 백필 → ADR/13.9-7로 기각됨
- 상위 계층 `override` 시 하위 코드 계층 반영 → ADR-0029 §6 미해결

## 2. 사전 실측 (STEP 0 — 추정 금지)

작업 시작 전 아래를 **실제 조회**하고 결과를 보고할 것. 스키마를 추정해 코드를 쓰지 않는다.

```bash
# 2-1. instance 3테이블 실제 스키마
docker compose exec postgres psql -U icfr -d icfr_db -c "\d process_instances"
docker compose exec postgres psql -U icfr -d icfr_db -c "\d sub_process_instances"
docker compose exec postgres psql -U icfr -d icfr_db -c "\d risk_instances"

# 2-2. action 컬럼에 실제로 들어가는 값 — enum 정의 위치 확인
grep -rn "action" backend/app/models/ | grep -iE "column|enum|varchar" | head -20

# 2-3. 어서션 junction 테이블 구조
docker compose exec postgres psql -U icfr -d icfr_db -c "\dt" | grep -iE "assertion"

# 2-4. 기존 resolver 3함수의 현재 시그니처와 반환 형태
sed -n '130,175p' backend/app/services/control_resolver.py
```

**보고할 것**
- `action` 컬럼에 허용되는 값의 실제 목록과 그 정의 위치 (ADR-0029 §2.6 판정의 근거)
- 3개 instance 테이블의 유니크 제약 (NULL 통과 문제가 process 외에도 있는지)
- 어서션 junction의 baseline / instance 분리 여부

**실측 결과가 ADR-0029의 전제와 다르면 즉시 중단하고 보고할 것.**
ADR을 고쳐야 하는 상황일 수 있고, 그러면 코드보다 ADR이 먼저다.

## 3. 구현 원칙

### 3.1 ADR-0020 준수
서비스 클래스·디자인 패턴·추상화 계층을 만들지 않는다.
직접 함수와 명시적 if 분기만 사용한다. `resolve_controls` 의 기존 구현 방식을 따른다.

### 3.2 cascade 판정 (ADR-0029 §2.1)
- 상위 제외 목록을 **한 번** 읽어 하위 필터링에 사용한다
- 하위 조회 시 부모 체인을 거슬러 올라가는 재귀 조회를 하지 않는다
- 하위 레코드를 물리적으로 변경하지 않는다

### 3.3 제외 상태 저장 금지 (ADR-0029 §2.2)
하위 instance는 자기 제외만 기록한다.
"상위로 인한 제외"를 컬럼에 저장하지 않는다. 조회 시점에 계산한다.

### 3.4 판정은 action 컬럼으로 (ADR-0029 §2.6)
`baseline_*_id IS NULL` 로 신규 여부를 판정하지 않는다.
`action` 값으로만 판정한다. 문자열 리터럴을 코드에 흩뿌리지 말고 정의된 상수/enum을 참조한다.

### 3.5 신규 추가 시 code 중복 검증 (ADR-0029 §3)
PostgreSQL에서 NULL은 유니크 제약을 통과한다.
`action='add'` 레코드는 `(tenant_id, baseline_*_id)` 제약의 보호를 받지 못한다.
**DB 제약에 의존하지 말고 핸들러에서 code 중복을 명시적으로 검증**하고,
사용자에게 의미 있는 에러 메시지를 반환할 것.

### 3.6 envelope
Regina 협의 A안 — 상위 계층 응답에 source 필드를 확장한다.
`resolve_controls` 가 이미 사용하는 envelope 형태와 **동일한 계약**을 유지한다.
flat 계약(nested 금지)을 지킬 것. 상위 계층만 다른 형태가 되면 FE가 분기해야 한다.

## 4. 커밋 분리

한 커밋 = 한 원인. 아래 순서로 분리한다.

1. `feat(rcm): 상위 3계층 조회 API resolver 전환 (2-A-4-3, ADR-0029)`
   — 조회 3개 핸들러 + envelope 확장 + 조회 테스트
2. `feat(rcm): 상위 3계층 CRUD overlay 전환 (2-A-4-3, ADR-0029)`
   — CRUD + code 중복 검증 + CRUD 테스트
3. `test(rcm): cascade 시맨틱 검증 케이스 추가 (ADR-0029 §5)`
   — 아래 §5 검증 조건 테스트

각 커밋 후 `ruff` + `pytest` 통과를 확인한다. 실패 상태로 다음 커밋에 넘어가지 않는다.

## 5. 검증 조건 (ADR-0029 §5)

테스트로 구현할 것. 5개 전부 통과해야 완료다.

1. `/processes` 조회가 baseline 8건 반환
2. 상위 제외 → 하위가 effective 제외로 계산됨
3. **하위 개별 제외 → 상위 제외 → 상위 복원 → 하위 개별 제외가 보존됨**
4. 통제 제외 시 어서션 연결도 effective 제외
5. `action='add'` 항목에 대해 2·3이 동일하게 동작

**3번이 이 작업의 핵심 검증이다.** 이것이 없으면 ADR-0029 §2.2가 구현됐다고 볼 수 없다.
2번만 통과하고 3번이 없으면, 제외 상태를 저장하는 구현으로도 통과해버린다.

4번은 §2에서 확인한 어서션 junction 구조에 따라 검증 방식이 달라진다.
구조 확인 후 적절한 형태로 작성할 것.

## 6. 완료 보고

1. STEP 0 실측 결과 (§2의 보고 항목 3건)
2. 커밋 3건의 해시와 각 커밋의 변경 파일
3. `ruff` 결과, `pytest` 결과 (passed / failed / xfailed 수치)
4. §5 검증 조건 5개의 테스트 함수명과 통과 여부
5. xfail 6건 중 본 작업으로 해소된 것과 남은 것
6. 로컬 검증만 완료된 상태임을 명시할 것 — 운영 확인은 마스터가 별도 수행

**실행하지 않은 항목을 완료로 보고하지 않는다.**
막힌 지점은 막힌 대로 보고할 것. 특히 실측이 ADR 전제와 어긋나면 코드를 맞추지 말고 보고한다.
