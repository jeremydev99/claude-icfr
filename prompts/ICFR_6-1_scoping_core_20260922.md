## 2. 설계 확정 사항

### 2.1 금액·반올림 — 원천과 한 원도 다르면 안 된다

- 금액은 **정수(원) 또는 Decimal**로 저장·계산한다. **float 금지**
- **Excel `ROUND`는 0.5를 0에서 멀어지는 쪽으로 반올림한다.** Python `round()`는
  은행가 반올림이라 결과가 다르다. `Decimal.quantize(..., ROUND_HALF_UP)`으로 구현할 것
  (음수도 0에서 멀어지는 쪽). 이걸 틀리면 §5-1 재현 검증이 깨진다
- 반올림 규칙은 원천 수식 그대로(ADR-0034 §2.3):
  ```
  벤치마크 산출액 = ROUND(기준값 × 비율, 0)
  전반중요성      = ROUND(벤치마크 산출액, -3)
  수행중요성      = ROUND(전반중요성 × 설정율, 0)
  ```

### 2.2 질적 판정 — 이상(≥), 정책으로

- H/M/L = 3/2/1, 10요소 평균 **≥ 2** 이면 질적 유의 (ADR-0034 §2.4, 2026-09-22 결정)
- 기준값(기본 2)과 비교 방식(기본 이상)을 `tenant_policies`에 둔다. 하드코딩 금지
- **10요소 중 하나라도 미입력이면 질적 미평가.** 원천처럼 빈칸을 0으로 합산하지 않는다
- 결론 = 양적 OR 질적. 양적 N + 질적 미평가 → 결론 미평가
- 템플릿에 넣는 설명 문구는 "초과"를 **"이상"으로 고쳐서** 넣는다

### 2.3 양적 판정이 해당 없는 항목

원천 주석 시트는 금액이 없는 항목이 많다(예: "1. 당사의 개요").
금액이 **없어서** 판정을 못 하는 것과 **입력을 안 해서** 못 하는 것은 다르다.
처리 방식을 판단하고 보고할 것 — 예: 항목별 "양적 판정 해당 없음" 표시를 두고,
그 경우 결론은 질적 판정만으로 낸다.

### 2.4 수동 판정

- 사유 필수. 계산 결론과 수동 결론을 **둘 다 보존**한다
- 원천 결론 열에는 수식 대신 `N`이 직접 입력된 행이 있다.
  **그 값이 계산 결론과 다른 행만** 수동 판정으로 시드할 것. 같으면 수동 판정이 아니다.
  몇 건인지 STEP 0에서 보고

### 2.5 템플릿과 배지

**템플릿은 제품 콘텐츠다.** 테넌트에 속하지 않는 전역 대상으로 둘지(ADR-0030 §2.4 산업별
템플릿과 같은 계층), 판단하고 보고할 것. 스코핑 생성 시 테넌트로 **복사**하며,
어느 템플릿·어느 버전에서 왔는지 기록한다.

**배지는 필드 단위다.** 한 계정의 한 질적 요소를 고치면 그 요소만 배지가 떨어진다.
- 출처 상태를 **불리언이 아니라 값 목록(enum)**으로 둘 것 — 지금은 `template` / `edited` 둘이지만,
  ADR-0034 §5의 "검토 확인" 상태가 나중에 추가된다. 불리언이면 그때 스키마를 또 바꿔야 한다
- **같은 값으로 다시 저장하는 것은 수정이 아니다.** 배지를 떼지 않는다
- 저장 구조(필드별 컬럼 / 별도 출처 테이블 / JSON)는 판단하고 근거와 함께 보고할 것

**템플릿에 넣는 것 / 넣지 않는 것**은 ADR-0034 §2.7 그대로.
특히 **2022년 금액 전부, 감사인 담당자 이메일(업무프로세스 시트), 주석 시트 FY2019 헤더는 제외.**
업무프로세스·GITC 시트는 6-2 범위이므로 이번엔 적재하지 않는다.

### 2.6 상태와 확정

- 확정 시: 배지 남은 필드 개수를 경고로 보여주고, 확정 사유를 기록한다. 막지 않는다
- 확정 시: **결론 스냅샷**을 남긴다. 결론은 평소 조회 시 산출하지만(ADR-0029 §2.2),
  확정 뒤 정책 기준을 바꿔도 확정 당시 판단은 보존되어야 한다
- 확정 후 수정 거부. 재오픈은 `icfr_manager` + 사유, 이력 기록
- 감사인 검토 결과는 `icfr_manager`가 기록 — 감사인·검토일·의견·증빙.
  증빙은 기존 증빙 모듈을 쓸 수 있는지 판단할 것(3-3). 새 저장 경로를 만들지 말 것

### 2.7 권한

작성·수정·상태 전이 = `icfr_manager`. `external_auditor` 조회만. 조회는 전원.
`require_write`로 기본 처리하지 말 것(13.9-35·41). 프론트 게이트는 `tenant_roles`.

### 2.8 값 상수 한 곳에

재무제표 종류 / 벤치마크 종류 6종 / 질적 요소 10종 / H·M·L / 스코핑 상태 / 배지 상태.
가이드 범위(ADR-0034 §2.3 표)도 상수로. **매출액 비율 범위는 원천 "0.0~5%"가 오기 의심이라
확인 전까지 경고 판정에 쓰지 않는다** — 범위 값을 비워두고 그 사실을 주석에 남길 것.

## 3. 사전 실측 (STEP 0)

```bash
cd backend && python -c "
import openpyxl
wb=openpyxl.load_workbook('seeds/4__내부회계관리제도_Scoping.xlsx',data_only=False)
for s in wb.sheetnames: print(s, wb[s].max_row, wb[s].max_column)
"
```

시트별로 확인하고 **보고할 것**:
1. 각 계정 시트(2.1~2.4)의 헤더 행·데이터 시작 행·질적 요소 열 위치 — 시트마다 한 칸씩 어긋난다
   (주석 시트는 "양적중요성 Factor" 열이 하나 더 있다)
2. **소계 행과 계정 행을 구분하는 방법.** `=SUM(...)` 수식 행은 소계로 보인다.
   구조(수식 여부)로 판정하고, 계정명 문자열로 판정하지 말 것(회귀 방지 원칙 1)
3. 결론 열이 수식이 아니라 직접 입력된 행 목록과, 그중 계산 결론과 다른 행 수(§2.4)
4. 템플릿 적재 대상 문구 목록 — 중요성 기준 시트의 가이던스·질적 10요소 설명·설정근거,
   각 계정 시트의 일반사항·판단 원칙, Notes 시트
5. §2.3 양적 판정 해당 없음 처리 방식
6. §2.5 템플릿 전역/테넌트 여부, 배지 저장 구조
7. 감사인 검토 증빙에 기존 증빙 모듈을 쓸 수 있는지
8. alembic head

**5·6·7은 구현 전에 보고하고 확인받을 것.**
실측이 ADR-0034 전제와 어긋나면 코드를 맞추지 말고 보고할 것.

## 5. 검증 조건

1. **원천 2022 수치 재현** — 조정세전순이익 4,818,843,993 × 5% → 벤치마크 산출액 240,942,200,
   전반중요성 **240,942,000**, 수행중요성 **168,659,400**. 원천 캐시값(`data_only=True`)과 대조.
   **테스트 픽스처로만 쓰고 시드하지 않는다**
2. 반올림 경계값 — x.5 양수·음수가 Excel `ROUND`와 같은 결과 (§2.1)
3. 원천 질적 평가값으로 계산 → 원천 결론과 일치. 평균이 정확히 2.0인 16건이 유의로 유지
4. 정책을 "초과"로 바꾸면 그 16건이 비유의로 바뀜
5. 10요소 중 하나 미입력 → 질적 미평가, 양적 N이면 결론 미평가
6. 수동 판정 — 사유 없으면 거부, 계산·수동 결론 모두 보존
7. **스코핑 생성 직후 템플릿 값 전부 배지. 한 필드 수정 → 그 필드만 해제. 같은 값 재저장 → 해제 안 됨**
8. 확정 시 배지 잔여 개수 경고 + 확정 사유 기록
9. 확정 후 수정 거부. 재오픈은 `icfr_manager` + 사유, 이력 기록
10. **확정 후 정책 기준을 바꿔도 확정 스냅샷의 결론은 그대로**
11. 비율·설정율이 가이드 범위 밖 → 경고, 저장 허용. 매출액 비율은 경고하지 않음
12. 템플릿에 2022 금액·감사인 이메일·FY2019 헤더가 없음
13. `external_auditor` 쓰기 전부 거부
14. 다른 테넌트 스코핑 접근 불가 (postgres에서 확인)
15. 전체 pytest 통과. **순차로 2회 반복** — 동시 실행 금지(13.9-47)

**1·3·7·10번이 핵심이다.**
1·3번은 원천을 정확히 옮겼는지, 7번은 배지가 필드 단위로 동작하는지,
10번은 확정 판단이 보존되는지 본다.
