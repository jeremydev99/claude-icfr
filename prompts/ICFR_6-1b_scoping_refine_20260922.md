# 6-1b: 스코핑 보완 — 검토 확인·기준 회사 설정·기준 연도·가독성

## 0. 배경 — 운영 화면에서 드러난 것

6-1 배포 후 2026 회계연도 스코핑을 만들었더니 상단에
**"아직 템플릿 그대로인 필드 1,889개"**가 표시됐다.

현재 규칙은 **수정해야만** 템플릿 배지가 떨어진다. 템플릿 판단에 동의하는 계정은
배지를 뗄 방법이 없어, 확정 시 경고가 1,800개 넘게 뜬다. 그 숫자는 정보를 주지 못하고
경고를 무시하게 만든다. 배지의 목적 — "회사가 아직 판단하지 않은 곳을 드러낸다" — 이 무너진다.
ADR-0034 §5에 미해결로 남겼던 문제가 실제로 확인된 것이다.

그 밖에 마스터 확인으로 정해진 것:
- 스코핑의 기준 금액은 **직전 연도 결산 확정 금액**이다. 화면의 "당기 금액"은 라벨이 틀렸다
- 중요성 기준(비율 가이드 범위 포함)은 **전부 회사가 설정**하고 감사인이 검토해 확정한다
- 판단 근거·수동 판정 칸이 좁아 글이 잘린다

## 1. 제도 운영 흐름 (마스터 확정, 2026-09-22)

```
회사가 기준 설정 → 감사인 검토·감사 → 확정 → 확정 기준으로 운영
 → 감사·감사위원회에 내부 보고, 승인
 → 지적 사항은 개선과제로 → 이듬해 개선
```

**이번 작업의 범위는 앞의 셋(설정·검토·확정)의 보완이다.**
감사위원회 승인·개선과제 연결·이듬해 이월은 이번에 구현하지 않고 기록만 한다(§6).
다만 이 흐름을 ADR-0034 §2.2에 정정 이력으로 남길 것 — 스코핑이 1년 주기의
첫 단계라는 사실이 설계 문서에 있어야 이후 Report·개선계획 모듈이 여기에 이어진다.

## 2. 범위

**포함**
1. "검토 확인" — 배지 상태에 `confirmed` 추가
2. 중요성 기준 전부 회사 설정 — 비율 가이드 범위·설정율 범위
3. 확정 스냅샷에 **기준값까지** 포함
4. 기준 연도 명시 + 두 해 비교
5. 판단 근거·수동 판정 가독성

**제외 → 재무제표 추출 ADR(후속)**
- **계정 계층(트리)** — 계정을 상위·하위 몇 단계든 둘 수 있게. 재무제표 계층·템플릿 매칭과
  같은 문제라 함께 설계한다. 실데이터가 없는 지금 이후에 해도 "처음부터"가 지켜진다
- 재무제표 업로드·추출·계정 매칭

## 3. 설계 확정 사항

### 3.1 검토 확인

배지 상태 값 목록에 `confirmed`를 추가한다(6-1에서 값 목록으로 열어둔 자리).

| 상태 | 의미 | 배지 |
|---|---|---|
| `template` | 템플릿 그대로, 아무도 보지 않음 | "템플릿" |
| `confirmed` | 템플릿 값을 **검토하고 동의함** | "확인됨" (구분되게) |
| `edited` | 회사가 **수정함** | 없음 |

- **계정 한 줄 단위로 "확인"** — 그 줄의 `template` 필드 전부를 `confirmed`로
- 양적 중요성 영역(벤치마크·비율·설정율·설정근거)에도 같은 "확인"을 둔다
- 확인한 사람·시각을 남긴다
- `confirmed` 필드를 나중에 수정하면 `edited`가 된다
- **확정 경고는 `template` 상태만 센다.** 경고 숫자가 "아직 아무도 보지 않은 곳"이 된다
- 확인 취소(`confirmed` → `template`)가 필요한지 판단하고 보고할 것

### 3.2 중요성 기준은 전부 회사 설정

지금은 비율 가이드 범위가 코드 상수다. **회사가 설정하는 값으로 바꾼다.**

- 벤치마크 6종의 비율 가이드 범위, 수행중요성 설정율 범위
- 기본값은 템플릿(원천 Note 1·2)에서 가져온다
- **매출액은 기본값을 비워둔다.** 원천 "0.0~5%"가 불분명하다. 비어 있으면 경고하지 않고,
  회사가 감사인과 합의한 범위를 넣으면 그때부터 경고한다
- 범위를 벗어나면 경고하고 저장은 허용한다(기존과 같음)

**저장 위치를 판단하고 보고할 것.** 이 기준들은 회계연도마다 감사인 검토를 거쳐 확정되는 값이다.
테넌트 정책(전 연도 공통)에 둘지, **회계연도 스코핑에 둘지**(새 연도 생성 시 직전 연도나
기본값에서 복사). 후자가 "매년 설정하고 확정한다"는 흐름에 맞아 보이나, 6-1에서 질적 기준을
`tenant_policies`에 둔 것과의 일관성을 함께 판단할 것.

### 3.3 확정 스냅샷에 기준값까지

6-1은 확정 시 **결론**을 스냅샷으로 남긴다. **그 결론을 낸 기준도 함께 남겨야 한다.**
- 선택 벤치마크·기준값·비율·전반중요성·설정율·수행중요성
- 질적 기준값·비교 방식
- 비율 가이드 범위

확정 후 기준을 바꿔도 "2026년에는 어떤 기준으로 무엇이 유의였나"가 그대로 보여야 한다.
감사인이 묻는 것이 정확히 이것이다. 현재 스냅샷에 무엇이 들어 있는지 STEP 0에서 확인할 것.

### 3.4 기준 연도와 두 해 비교

- 스코핑에 **기준 재무제표 연도**를 명시적으로 저장한다. 기본값은 스코핑 회계연도 − 1
  (2026 스코핑 → FY2025 결산). 변경 가능
- 라벨: "당기 금액" → **"기준 금액 (FY2025 결산)"** — 연도는 저장값에서
- **전년 금액 칸을 추가**한다(FY2024). 원천도 두 해를 나란히 뒀다
- 증감률을 표시한다. 질적 6번 요소(계정 성격·금액 변화 정도)를 판단하는 근거가 된다
- 양적 판정은 **기준 금액**으로만 한다. 전년 금액은 비교용

### 3.5 가독성

판단 근거·수동 판정 칸이 한 줄만 보이고 잘린다.
- 입력 내용에 맞춰 높이가 늘어나게
- 폭을 넓힐 것. 다른 열과의 균형은 판단
- 긴 글은 펼쳐서 전체를 볼 수 있게

## 4. 사전 실측 (STEP 0)

보고할 것:
1. 현재 배지 출처 테이블 구조와 `confirmed` 추가 시 마이그레이션 필요 여부
2. 현재 확정 스냅샷에 들어가는 항목
3. 비율 가이드 범위가 지금 어디에 정의돼 있는지
4. §3.2 저장 위치 판단 (근거 포함)
5. 운영 2026 스코핑에 사용자가 입력한 값이 있는지 — 마이그레이션 영향 범위

**4는 구현 전에 보고하고 확인받을 것.**

## 5. 검증 조건

1. 계정 한 줄 "확인" → 그 줄의 템플릿 필드 전부 `confirmed`, 확인자·시각 기록
2. `confirmed` 필드 수정 → `edited`
3. **확정 경고 숫자 = `template` 상태만.** 전부 확인하면 0
4. 매출액 가이드 범위가 비어 있으면 어떤 비율을 넣어도 경고 없음. 범위를 넣으면 경고 동작
5. 다른 벤치마크 범위를 회사가 바꾸면 경고 기준이 바뀜
6. **확정 후 기준을 바꿔도 스냅샷의 기준값·결론이 그대로**
7. 기준 연도가 2026 스코핑 → FY2025로 표시되고, 바꾸면 라벨이 따라감
8. 전년 금액 입력 시 증감률 표시. 양적 판정은 기준 금액만 사용
9. 판단 근거 긴 글이 잘리지 않고 보임
10. 기존 6-1 검증(원천 재현 1·3, 배지 7, 스냅샷 10) 회귀 없음
11. 전체 pytest **순차 2회**

**3·6번이 핵심이다.** 3번은 경고가 의미를 되찾는지, 6번은 확정 기준이 보존되는지 본다.

## 6. 기록만 할 것 (ClaudeICFR.md 13.9)

- 제도 운영 흐름(§1)과 각 단계를 담을 모듈:
  감사위원회 내부 보고·승인 → Report / 지적 사항 → 개선계획 / 이듬해 이월 → 스코핑
- 스코핑 지적 사항을 개선과제로 넘기는 연결
- 이듬해 스코핑을 직전 연도 확정본에서 시작하는 이월(ADR-0034 §5)

## 7. ADR-0034 정정 이력

덮어쓰지 말고 정정 이력으로 남길 것.
- §2.2 — 제도 운영 흐름 전체(§1)
- §2.3 — 비율 가이드 범위는 회사 설정. 매출액 기본값 비움
- §2.4 — 기준 금액은 직전 연도 결산 확정 금액, 두 해 비교
- §2.7·§5 — "검토 확인" 결정(미해결 → 결정), 1,889개 경고 실측 근거
- §2.2·§3 — 확정 스냅샷에 기준값 포함
