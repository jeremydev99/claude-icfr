# ICFR_backend_fs-8a_20260928 — 재무제표·계정 트리 8-A: 데이터 구조와 검증

**필요 모델: Opus — STEP 0과 구현 모두. 현재 모델이 다르면 시작하지 말고 보고할 것** (금액 계산·검증 로직 포함)
**push: 마스터 직접** (마이그레이션 포함 — 자동 push 금지)

## 배경과 범위 경계
"재무제표가 계정 행을 정하고, 템플릿은 매칭으로 기본값만 공급한다"는 구조를 다섯 단계로 나눈다. 이 작업은 **8-A(데이터 구조와 검증)** 이다.

- **8-A(이번)**: 계정 트리, 재무제표, 금액 테이블 + 검증 규칙 + 조회·확정 API + ADR(전체 설계).
- 8-B 엑셀 업로드 파서 2종(가로 연도형·공시양식형) / 8-C 템플릿 매칭 / 8-D 화면 / 8-E 스코핑 연결.
- **ADR에는 8-A~8-E 전체 설계를 한 번에 확정해 적는다.** 나중에 구조를 뒤집지 않기 위해서다.
- **이번 작업은 업로드 화면이 없으므로 배포해도 사용자 눈에 보이는 변화가 없다.** 데이터는 8-B에서 들어온다.

## 반드시 지킬 것 — 기존 스코핑 비침습
2026 스코핑이 작성 중이고 템플릿 배지가 1,897개 붙어 있다. **이번 작업에서 기존 스코핑 관련 테이블·코드·시드를 일절 변경하지 않는다.** RCM baseline/instance 때와 같은 병행 신규 구축이다. 스코핑이 새 구조를 쓰도록 바꾸는 것은 8-E이며, 그때 기존 스코핑 이관 방침을 따로 정한다.

## 확정된 결정
1. **계정은 회사 단위 마스터 하나, 금액은 연도별로 따로.** 재무제표마다 계정 트리를 복제하지 않는다. 연도 비교가 계정 매칭 문제로 바뀌고, 스코핑이 계정을 참조할 때 어느 연도 것인지 애매해지기 때문이다.
2. **트리는 `parent_id` + 정렬 순서**(adjacency list). 무한 가지치기를 이것으로 표현하고 조회는 재귀 CTE로 한다. 별도 경로·closure 테이블은 만들지 않는다.
3. **판별은 구조로 한다.** 계정이 자산인지 부채인지를 이름으로 판정하지 않는다. `section`(자산·부채·자본·수익·비용 등) 값과 `is_subtotal` 플래그로 판정한다. 검증 로직에 계정명 문자열 비교를 넣지 않는다.
4. **연결·별도 구분을 지금 넣는다.** 회사는 현재 별도만 쓰지만, 나중에 넣으면 마이그레이션이 한 번 더 필요하다. 화면 노출은 이번 범위가 아니다.
5. **금액은 `Numeric`.** float를 쓰지 않는다. 정밀도는 기존 선례에 맞춘다(STEP 0에서 확인).
6. **단위(원·천원·백만원)와 통화를 재무제표 단위로 저장한다.** 단위를 잘못 읽으면 검증이 엉뚱한 곳에서 깨진다.
7. **원본 보존 컬럼을 금액 행에 둔다** — 원본 행번호, 원본 표기 계정명, 원본 들여쓰기 수준 등. 8-B 파서가 무엇을 읽든 담을 수 있게 해서, 파서를 만들 때 구조를 고치지 않아도 되게 한다.
8. **검증은 확정을 막는 관문이다.** 자산=부채+자본, 소계=하위합이 맞지 않으면 `final` 전환을 거부한다. 경고만 남기고 통과시키지 않는다. 검증 결과는 어긋난 계정과 차액을 항목별로 돌려준다.
9. **상태는 draft / final.** 가로 연도형에서 최신 연도를 자동으로 final로 두는 규칙은 8-B 파서가 적용한다. 8-A는 상태 전환과 검증만 책임진다.
10. **계정의 신설·폐지**는 행을 지우지 않고 유효 회계연도 범위로 표현한다.
11. **템플릿 매칭(8-C) 방침을 ADR에 미리 적는다**: 자동 매칭은 제안일 뿐이고 사람이 확인한 링크만 저장한다. 확정된 링크만 기본값 공급에 쓴다. 매칭 근거(정확일치·정규화일치·수동)를 함께 남긴다.

## STEP 0 — 실측·설계 보고 후 멈춤 (코드·DB·설정 수정 금지)

1. **기존 계정 구조 실측**: 스코핑 템플릿 계정(192건)과 스코핑 화면의 계정 섹션이 실제로 어떤 테이블·컬럼으로 되어 있는지 확인한다. 새 계정 마스터와 이름·역할이 겹치는 부분을 짚고, 혼동을 피할 명명을 제안한다.
2. **중복 확인**: 재무제표·계정·금액에 해당하는 테이블이 이미 있는지 확인한다.
3. **베이스 클래스**: 새 테이블은 tenant 종속이므로 `AuditedBase`를 쓴다. 13.9-51 감사 컬럼 자동 기록과 자동 tenant 격리가 그대로 적용되는지 확인한다.
4. **Numeric 선례**: 기존 금액 컬럼(스코핑 중요성 금액 등)의 정밀도·스케일을 확인하고 같은 기준을 제안한다.
5. **재귀 CTE 선례**: 현재 SQLAlchemy 버전에서 재귀 CTE를 쓴 선례가 있는지 확인한다. 없으면 이번에 쓸 방식을 제시한다.
6. **enum·상수 관리 선례**: `CYCLE_KINDS` 같은 기존 상수 패턴을 확인하고, `statement_type`·`basis`·`section`·`status`를 같은 방식으로 둘지 제안한다.
7. **업로드 선례(읽기만)**: RCM 엑셀 업로드의 preview/commit 구조를 확인한다. 8-B에서 그대로 따를 수 있는지만 보고한다. **이번에 구현하지 않는다.**
8. **스코핑 참조 지점 목록**: 스코핑이 계정을 참조하는 코드 위치를 목록으로만 뽑는다. 8-E에서 바꿀 대상이며 **이번에는 건드리지 않는다.**
9. **재무제표 종류 범위**: 이번에 다룰 것이 재무상태표·손익계산서 둘인지, 현금흐름표·자본변동표까지 컬럼으로 열어둘지 제안한다.
10. **alembic head와 충돌**: `git fetch` 후 원격 변경, 현재 head, Regina 리비전 충돌 여부를 확인한다.
11. **ADR 번호**: `docs/adr/` 최대 번호를 확인하고 다음 번호를 제안한다.

**보고 형식**: 1~11을 항목별로 짧게. 끝에 제안 스키마(테이블·컬럼·제약), 커밋 분할, 마스터 확인 질문을 둔다. **여기서 멈춘다.**

## 구현 (마스터 확인 답을 받은 뒤)

### 커밋 분할 (한 커밋 = 한 원인, 이 순서)
1. **모델·마이그레이션**: 계정 마스터, 재무제표 헤더, 금액 행 3개 테이블 + 마이그레이션(신규 테이블만). 순환 참조를 막는 제약 또는 검사도 포함.
2. **검증 서비스**: 자산=부채+자본, 소계=하위합, 단위·부호 규칙. 어긋난 계정과 차액을 항목별로 돌려준다. 계정명 문자열 비교를 쓰지 않는다.
3. **조회·확정 API**: 계정 트리 조회(재귀 CTE), 재무제표 목록·상세(트리 형태 금액 포함), 검증 결과 조회, `final` 전환(검증 실패 시 거부).
4. **테스트**: 아래 검증 항목.
5. **문서**: ADR(8-A~8-E 전체 설계), ClaudeICFR.md 해당 항목·§14, 밀린 백로그 4건 등록(시드별 출처명 기록 테스트 / 운영 백업 정책 ADR + 정기 백업 / §11 용어집 확장 — 설계평가·운영평가·통제유형·미비점 / 운영 이미지에서 tests 제외 검토), 이 프롬프트 파일.

### 검증 (보고 시 표로)
1. 3단 이상 깊이의 트리 저장·조회
2. 자기 자신 또는 자기 자손을 부모로 지정하면 거부
3. 자산=부채+자본 — 맞는 경우 통과, 틀린 경우 차액과 함께 실패
4. 소계=하위합 — 맞는 경우 통과, 틀린 경우 어느 소계 계정인지와 차액을 반환
5. 검증 실패 상태에서 `final` 전환 거부
6. 단위가 다른 재무제표를 각각 저장하고 검증이 각 단위 기준으로 동작
7. 같은 연도에 연결·별도 재무제표가 공존
8. 계정 폐지 후 과거 연도 금액은 그대로 조회됨
9. tenant 격리 회귀 없음
10. 감사 컬럼에 사용자 id가 기록됨(13.9-51)
11. **기존 데이터 불변 확인** — 마이그레이션 전후로 `scopings`, `scoping_field_origins`, `baseline_controls` 건수가 같음. 실 DB에서 확인하고 숫자를 보고한다
12. 마이그레이션 실 DB 적용·downgrade 왕복
13. 백엔드 전체 순차 2회 + ruff

### push·배포 (마스터 실행 — 명령만 제시)
1. 서버 백업 명령
2. push 전 확인: `git fetch` → `HEAD..origin/main` 비어 있는지, alembic 리비전 충돌 없는지
3. push
4. 배포 후 alembic 리비전 확인
5. 기존 테이블 건수가 배포 전후로 같은지 확인하는 psql 명령

**자동 push 금지.** 로컬 커밋까지만 하고, 커밋 해시와 검증 표로 보고한다.
