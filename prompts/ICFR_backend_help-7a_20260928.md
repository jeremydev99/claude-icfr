# ICFR_backend_help-7a_20260928 — 매뉴얼 패널 7-A: 백엔드 틀·키 규칙·문구 초안

**필요 모델: Opus — STEP 0(실측·보고 후 정지). 현재 모델이 다르면 시작하지 말고 보고할 것**
**구현: Sonnet으로 이어서 (신규 테이블만, 기존 데이터 미변경)**
**push: 마스터 직접** (마이그레이션 포함 — 자동 push 금지)

## 배경과 범위 경계
ADR-0035 매뉴얼 패널을 두 단계로 나눈다. 이 작업은 **7-A(백엔드 틀·키 규칙·문구 초안)** 이다.

- **7-A(이번)**: 문구 저장 테이블, 키 규칙, 조회 API, 문구 초안 적재, 검증 테스트.
- **7-B(다음, 별건)**: 우측 패널 UI(본문 밀림, 폭 조절, 좁은 화면 겹침). Regina의 Test 전환 push가 끝난 뒤 착수한다. **이번 작업에서 프론트엔드 파일은 건드리지 않는다.** 전역 레이아웃이 Regina 작업과 충돌한다.
- 6-2를 막고 있는 것은 패널 UI가 아니라 키 규칙이므로, 7-A만으로 6-2가 풀린다.

## 확정된 결정
1. **테이블**: `help_texts` 한 개. tenant 비종속(`IdentityBase`). 도움말은 제품이 제공하는 문구이고 회사 데이터가 아니다. `scoping_templates`와 같은 자리다.
2. **컬럼**: `key`, `locale`, `title`, `body`, `baseline_version`, `sort_order` + 베이스 공통 컬럼. unique는 `(key, locale)`. locale은 `ko` 고정으로 넣어 둔다(나중에 붙이면 unique 제약을 바꿔야 하므로 지금 넣는다).
3. **회사별 문구 수정(overlay) 테이블은 만들지 않는다.** 키가 전역 고유하므로 나중에 overlay 테이블만 추가하면 된다. 이 확장 가능성을 ADR에 적는다.
4. **키 규칙** — 이름 매칭이 아니라 구조에서 파생한다.
   - `menu.<route>` — 메뉴. `navigation.ts`의 route에서 파생.
   - `screen.<route>.<섹션>` — 화면 안의 섹션.
   - `field.<모듈>.<API 필드명>` — 항목. 필드명은 실제 스키마의 snake_case를 그대로 쓴다.
   - `action.<모듈>.<동작>` — 버튼·동작.
   - `term.<용어>` — 용어.
   - 키에는 소문자·숫자·`-`·`.`만 쓴다. 정규식으로 형식을 검증한다.
5. **이번 시드 범위**: `menu.*`, `screen.*`, `term.*`. `field.*`와 `action.*`은 **규칙만 정의하고 문구는 넣지 않는다**(모듈 작업에서 붙인다).
6. **문구 원본은 데이터 파일**로 둔다(예: `backend/app/seeds/data/help_texts_ko.json`). 시드는 그 파일을 읽어 upsert한다. 마스터는 이 파일 하나를 검토한다.
7. **조회 API만 만든다.** 문구 수정은 시드 재적재로 한다. 편집 화면·쓰기 API는 7-C로 미룬다(스키마 변경 없이 추가 가능).
8. 시드는 13.9-51에 따라 `system_actor("system:seed-help")`로 감싼다.
9. 기존 문구를 덮어쓸 때도 `created_by`는 유지된다(리스너 규칙). 시드는 멱등이어야 한다.

## 문구 작성 원칙 (중요)
- **ADR·ClaudeICFR·명세 문장을 그대로 복사하지 않는다.** 내부회계 실무자가 그 화면을 처음 열었을 때 필요한 말로 쓴다.
- 각 항목이 답해야 하는 것: ① 여기는 무엇을 하는 곳인가 ② 여기서 무엇을 결정·입력하는가 ③ 흔히 틀리는 점 또는 주의할 점(있을 때만).
- `title`은 한 줄, `body`는 2~5문장. 불릿은 쓰지 않는다.
- 약어는 처음 나올 때 풀어 쓰고, 해당 `term.*` 키가 있으면 본문에서 그 용어를 그대로 표기해 나중에 연결할 수 있게 한다.
- 모르는 화면은 문구를 지어내지 말고 `body`를 비운 채 키만 만들고, 보고에 "문구 미작성" 목록으로 올린다.

## STEP 0 — 실측·설계 보고 후 멈춤 (코드·DB·설정 수정 금지)

1. **ADR-0035 원문**: `docs/adr/`에서 ADR-0035 파일이 실제로 있는지 확인하고, 있으면 요건을 그대로 인용해 이 프롬프트의 결정과 어긋나는 점을 보고한다. 파일이 없고 번호만 예약된 상태라면 그렇게 보고한다.
2. **메뉴 실측**: `navigation.ts`(또는 실제 단일 진실 공급원)에서 메뉴·route 전체 목록과 개수를 뽑는다. 개수를 가정하지 않는다.
3. **화면 섹션 실측**: 각 route의 화면 컴포넌트에서 실제 존재하는 섹션(탭·카드·패널 제목)을 뽑아 `screen.*` 키 목록을 확정한다. **읽기만 한다.**
4. **기존 구현 확인**: `help`, `tooltip`, `glossary`, `용어`, `도움말`로 저장소를 훑어 이미 있는 도움말·툴팁·용어 구현이 있는지 확인한다. 있으면 중복을 피할 방법을 제시한다.
5. **선례 대조**: `IdentityBase`·`AuditedBase` 정의와 `scoping_templates` 계열 테이블·시드 구조를 확인하고, 그 패턴을 그대로 따를 수 있는지 본다.
6. **용어집**: ClaudeICFR.md §11 용어집 항목 수와 내용을 확인해 `term.*` 키 목록을 만든다.
7. **권한**: 조회 API에 쓸 인증·권한 의존성과 `sys_admin` 판별 방식을 확인한다.
8. **alembic head와 충돌**: `git fetch` 후 원격 변경, 현재 alembic head, Regina 리비전과의 충돌 여부를 확인한다.
9. **ADR 번호**: 1번 결과에 따라 — ADR-0035 파일이 있으면 키 규칙을 그 ADR에 절로 추가할지, 없으면 ADR-0035로 새로 쓸지 제안한다. `docs/adr/` 최대 번호도 함께 보고한다.
10. **키 목록 규모 보고**: `menu.*` N개, `screen.*` M개, `term.*` K개로 이번에 작성할 문구 총량을 숫자로 보고한다.

**보고 형식**: 1~10을 항목별로 짧게. 끝에 구현 계획(파일, 커밋 분할)과 마스터 확인 질문을 둔다. **여기서 멈춘다.**

## 구현 (마스터 확인 답을 받은 뒤)

### 커밋 분할 (한 커밋 = 한 원인, 이 순서)
1. **모델·마이그레이션**: `help_texts` 신규 테이블 + 마이그레이션(신규 테이블만).
2. **키 규칙·조회 API**: 키 형식 검증, `GET /api/help?prefix=`(라우트 단위 일괄 조회), `GET /api/help/{key}`(단건). 없는 키는 404.
3. **문구 데이터·시드**: 데이터 파일 + 시드 스크립트(`system:seed-help`, 멱등 upsert). 실행 진입점을 `run_all`과 동일한 방식으로 연결한다.
4. **테스트**: 아래 검증 항목.
5. **문서**: ADR(9번 결론대로), ClaudeICFR.md 13.9 해당 항목·§14 변경로그, 백로그 "시드별 출처명 기록 테스트"(13.9-51 후속) 추가, 이 프롬프트 파일.

### 검증 (보고 시 표로)
1. `menu.*` 키가 실제 route와 1:1로 맞는지 — 존재하지 않는 route 키가 있으면 테스트 실패
2. 키 형식 정규식 위반 시 실패
3. 커버리지 리포트: 문구가 비어 있는 키 목록 출력
4. `term.*` 적재 건수 = 용어집 항목 수
5. 조회 API: prefix 조회, 단건 조회, 없는 키 404, 미인증 401
6. 시드 2회 실행 — 멱등(건수 불변, `created_by` 불변)
7. 감사 컬럼에 `system:seed-help`가 기록되는지
8. 마이그레이션 실 DB 적용·downgrade 왕복(테이블 drop→재생성), 기존 데이터 불변
9. 백엔드 전체 순차 2회 + ruff
10. **문구 복사 점검**: 작성한 `body` 중 ADR 파일·ClaudeICFR.md와 20자 이상 연속 일치하는 문장이 있는지 스크립트로 확인하고, 있으면 다시 쓴다

### 보고
- 문구 데이터 파일 경로와 키별 항목 수를 적는다. 마스터가 이 파일을 검토한 뒤 push하므로, **문구 미작성 키 목록**을 반드시 함께 올린다.
- 로컬 커밋까지만 하고 멈춘다.

4. 배포 후 마이그레이션 적용 확인
5. **운영 시드 실행 명령** (help 문구 적재)
6. 적재 확인 조회: 키 접두사별 건수와 `created_by = system:seed-help` 확인
