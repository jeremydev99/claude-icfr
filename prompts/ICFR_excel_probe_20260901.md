## 0. 이 작업의 성격 — 조사이지 수정이 아니다

**코드를 고치지 않는다. 원인 특정까지만 한다.**

이유가 있다. 13.6은 "멀티헤더 구조에서 0건 파싱"으로 기록돼 있으나
**재현 파일이 특정되지 않았고, 원인도 확인된 적이 없다.**
Regina의 FE 조사(2026-08-24)로 "FE는 파싱에 관여하지 않는다"까지만 밝혀졌다.

재현하지 못하는 버그를 고치면, 고쳤다고 믿고 넘어간 뒤 고객사 온보딩에서 다시 터진다.
먼저 실제로 무슨 일이 일어나는지 본다.

**주의 — 아래를 사실로 전제하지 말 것**
- "통제 93건이 정상 조회되므로 파서가 동작한다"는 **거짓이다.**
  93건은 `seed_baseline.py` 경로로 들어갔으며 `upload-excel` 파서와 무관하다
- 13.6의 "멀티헤더" 서술이 실제 원인인지 확인된 바 없다. 추정으로 기록됐을 수 있다

## 1. 범위

**포함 — 조사와 기록만**
- 대상 엑셀 파일을 `upload-excel` 경로로 처리했을 때의 실제 결과 확인
- `seed_baseline.py`와 `upload-excel`이 같은 파일을 어떻게 다르게 읽는지 대조
- 0건이 발생한다면 그 지점 특정
- `test_excel_upload_commit`이 xfail인 실제 사유 확인
- ClaudeICFR.md 13.6 기록 정정

**제외**
- 파서 수정 — 원인 특정 후 별건
- `upload-excel`의 overlay 전환 — 별건
- 운영 서버 적용 — **로컬 한정.** 파서가 baseline에 쓰는지 instance에 쓰는지
  확인되지 않은 상태이므로 운영 DB에 예상치 못한 데이터가 들어갈 수 있다

## 2. 조사 절차

### 2.1 대상 파일 구조 실측

```bash
cd backend
python -c "
import openpyxl
wb = openpyxl.load_workbook('seeds/2026_설계평가_RCM_리스트.xlsx', read_only=True)
print('시트:', wb.sheetnames)
for ws in wb.worksheets:
    print(f'--- {ws.title}: {ws.max_row}행 x {ws.max_column}열')
    for i, row in enumerate(ws.iter_rows(max_row=8, values_only=True), 1):
        print(i, [str(c)[:20] if c is not None else None for c in row])
"
```

**보고할 것** — 시트 구성, 헤더가 몇 행에 걸쳐 있는지, 데이터 시작 행.
"멀티헤더"라는 서술이 이 파일에 실제로 해당하는지 판정할 것.

### 2.2 두 경로 대조

```bash
grep -n "openpyxl\|load_workbook\|read_excel\|header" backend/seeds/seed_baseline.py | head -20
grep -n "openpyxl\|load_workbook\|read_excel\|header" backend/app/api/rcm.py | head -20
```

**보고할 것**
- `seed_baseline.py`가 헤더 행을 어떻게 건너뛰는지 (skiprows/header 인자 등)
- `upload-excel` 핸들러가 같은 지점을 어떻게 처리하는지
- **두 경로의 차이를 코드 인용으로 제시할 것.** 차이가 없으면 없다고 보고

### 2.3 실제 파싱 시도

`upload-excel` 핸들러를 로컬에서 이 파일로 실행한다.
가능하면 테스트 클라이언트 경유(엔드포인트 그대로), 어려우면 파서 함수 직접 호출.
**어느 방식을 썼는지 명시할 것.** 엔드포인트 경유가 아니면 검증 강도가 다르다.

확인할 것:
- 파싱 결과 건수 (0건인지, 93건인지, 다른 수인지)
- 반환된 에러·경고 메시지 원문
- 0건이면 **어느 단계에서 0이 되는지** — 헤더 인식, 행 순회, 검증 필터 중 어디인지

### 2.4 xfail 사유 확인

```bash
grep -n -B5 -A20 "test_excel_upload_commit" backend/tests/*.py
```

**보고할 것** — 이 테스트가 쓰는 입력이 무엇인지(실제 엑셀 파일인지 픽스처인지),
xfail 마커에 적힌 사유가 무엇인지, 그 사유가 13.6과 같은 건인지 다른 건인지.

## 3. 판정 기준

조사 결과는 셋 중 하나다. **어느 쪽인지 명확히 결론지을 것.**

| 결과 | 의미 |
|---|---|
| 정상 파싱됨 | 13.6은 다른 파일·다른 조건의 문제였다. 재현 자료 없이 기록만 남아 있던 것 |
| 0건 또는 오류 | 재현 성공. 원인 지점을 특정해 별건 수정으로 넘긴다 |
| 실행 불가 | 왜 실행할 수 없는지 보고. 억지로 우회하지 말 것 |

**"아마 이럴 것"으로 결론짓지 않는다.** 실행 결과로만 판정한다.
