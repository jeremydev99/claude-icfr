# PROMPT — 통제 4건 사전 조사 (읽기 전용)

## 목적
아래 4건을 구현하기 전에 **실제 코드·DB 상태를 확인**하고, 건별로 **추천안 1개**를 도출한다.
이번 작업은 **조사만** 한다. 코드·DB·설정 파일을 수정하지 않는다(산출물 md 1개 생성만 허용).

## 공통 규칙
- **DB는 추정 금지.** 반드시 실제 DB에 접속해 스키마·데이터를 조회한 결과로 판단한다.
  - 먼저 환경을 띄운다: 프로젝트의 docker-compose / 실행 스크립트를 찾아 DB·백엔드를 기동 (`docker compose up -d` 등, 프로젝트 기준 명령 사용).
  - 테이블 구조는 `\d <table>`(PostgreSQL) / `DESCRIBE <table>`(MySQL) 또는 migration·ORM 모델과 **실DB를 대조**한다. 불일치가 있으면 기록.
  - 조회는 SELECT만. INSERT/UPDATE/DELETE/DDL 금지.
- 코드는 필요한 부분만 grep → 해당 구간만 읽는다(전체 통독 금지).
- 각 건마다 **프론트 / 백엔드 API / DB** 3계층을 모두 확인한다.
- 인프라·권한 설계는 **외부 기업·기관 판매 수준**(감사추적·서버측 권한검증·직무분리) 기준으로 평가한다.
- 추천안은 **원칙 부합안 1개**. 회귀 위험이 큰 경우에만 "명시적 폴백"을 1줄로 덧붙인다.

## 조사 1 — 승인할 통제 건수 (자기승인 제외 · 직무분리 경고)
확인 항목:
1. "승인할/승인 대기" 건수를 표시하는 화면 컴포넌트와 이를 공급하는 API·쿼리 위치.
2. 통제(또는 테스트/증빙) 테이블의 **작성자·수행자·승인자·상태** 컬럼 실존 여부와 실제 값 분포
   (예: `SELECT status, COUNT(*) ... GROUP BY status`).
3. 현재 건수 집계에 **자기 작성 건이 포함되는지**(로그인 사용자 = 작성자/수행자 조건 유무).
4. 승인 처리 API에서 **자기승인을 서버측에서 차단하는지** 여부(화면만 막는지).
5. 직무분리(SoD) 판정에 쓸 기준 데이터 존재 여부: 사용자 역할, 통제 담당자/승인자 지정 매핑, 부서 등.
6. 감사로그(승인 이력) 테이블 존재 여부.

## 조사 2 — 증빙 Ctrl+V 붙여넣기
확인 항목:
1. 증빙 업로드 UI 컴포넌트(드래그앤드롭/파일선택 구현 방식, 사용 라이브러리).
2. 업로드 API: 요청 형식(multipart 등), 허용 MIME/확장자, 용량 제한, 저장소(로컬/S3 등), 파일명 생성 규칙.
3. 증빙 메타 테이블 구조(원본파일명, 해시, 업로더, 업로드시각 등) — 실DB 확인.
4. 클립보드 이미지(`image/png`, 파일명 없음)를 **기존 업로드 경로 그대로** 태울 수 있는지, 막히는 지점(파일명 필수, 확장자 검증 등).
5. 붙여넣기 이벤트를 걸 적절한 범위(모달/영역 포커스 기준) — 다른 입력창 붙여넣기와 충돌 여부.

## 조사 3 — RCM AW열 통제현황 → 테스트절차 영역 표시
확인 항목:
1. RCM 엑셀 import 코드에서 **AW열**의 헤더명과 현재 처리(매핑/무시) 여부. 실제 샘플 RCM 파일이 있으면 AW열 헤더·값 예시 확인.
2. AW열 값을 저장할 DB 컬럼 존재 여부 — 실DB 스키마 확인. 없으면 어느 테이블에 두는 게 맞는지(RCM 통제 마스터 vs 테스트).
3. 기존 import 데이터 재적재 필요 여부(이미 올라간 RCM에 값이 비어 있게 되는지).
4. "테스트절차" 영역 화면 컴포넌트와 데이터를 주는 API — AW 값을 응답에 포함시키는 지점.
5. 열 위치(AW) 하드코딩인지 헤더명 기반 매핑인지 — 양식 변경 시 깨질 위험.

## 조사 4 — 증빙관리 메뉴 관리자 전용
확인 항목:
1. 메뉴 정의 위치(하드코딩/DB 메뉴테이블)와 현재 권한별 노출 방식.
2. 프론트 라우트 가드 존재 여부 — URL 직접 접근 시 진입 가능한지.
3. 증빙관리 관련 **백엔드 API 전체 목록**과 각각의 권한 검증 유무(관리자 role 체크).
4. 역할(role) 체계 실DB 확인: 사용자-역할 테이블, "관리자" 식별 값.
5. 일반 사용자가 **다른 화면(통제 수행 등)에서 증빙 업로드/조회**를 쓰는지 — 관리자 전용화 시 그 기능이 깨지는지(API 공유 여부).
